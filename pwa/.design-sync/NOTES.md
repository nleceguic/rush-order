# design-sync notes — rush-order-pwa

- **This is not a published component library.** `pwa/` is the full Rush Order customer PWA (Vite + React 18 + TS). There is no dedicated design-system package, no `dist/index.js` with named exports, no Storybook. The synced "design system" is `src/shared/components/` (7 files: Badge, Button, Modal, PwaInstallBanner, SkipLink, Spinner, Toast). The converter runs in **synth-entry mode** (`cfg.srcDir` scoped to that folder) since there's no library build to point `--entry` at.
- **`Toast.tsx` exports `ToastContainer`** (the actual component), not `Toast` — `toast` (lowercase) is a plain helper object for triggering toasts, not a component, and is correctly excluded from the component scan.
- **No standalone stylesheet — Tailwind utility classes only**, config in `pwa/tailwind.config.ts`. `esbuild` (used by the converter) does **not** run PostCSS/Tailwind's JIT, so the raw `src/shared/styles/globals.css` (just `@tailwind base/components/utilities;` + custom rules) would ship with zero expanded utility classes if used directly as `cssEntry`.
  - **Workaround**: `cfg.cssEntry` points at `.design-sync/tailwind-build.css`, a copy of the real Vite-built, PostCSS-processed CSS (`dist/assets/index-*.css`) — verified it contains real rules like `.bg-rush-red{...}`.
  - **Re-sync risk**: this file goes stale the moment `src/**` changes without a rebuild. `cfg.buildCmd` (`npx vite build && cp dist/assets/index-*.css .design-sync/tailwind-build.css`) regenerates it — **always run this before re-running the converter**, since a plain `git pull` won't touch it.
  - The Vite build output filename is content-hashed (`index-<hash>.css`) and changes every build; the `cp dist/assets/index-*.css ...` glob picks whichever one exists, so don't hardcode the hash anywhere.
- **Fonts**: Poppins ships via the `@fontsource/poppins` npm package (imported directly in `src/app/main.tsx` as `400.css`/`500.css`/`600.css`/`700.css`), not a repo-owned font file. Wired via `cfg.extraFonts` pointing at `node_modules/@fontsource/poppins/{400,500,600,700}.css` — these are real `@font-face` rules with local relative `url()`s to woff2/woff files in the same npm package, so the extraFonts copier picks up the actual font binaries.
- **Path aliases**: `tsconfig.json` defines `@shared/*`, `@app/*`, `@features/*`. `Modal.tsx` and `PwaInstallBanner.tsx` import from `@shared/hooks/*` — `cfg.tsconfig` is set so esbuild resolves these when bundling from `src/shared/components`.
- **Package manager**: npm (`package-lock.json`), Node version not pinned in-repo (no `.nvmrc`).
- **REQUIRED one-time setup: a `node_modules/rush-order-pwa` self-junction.** `rush-order-pwa` isn't a published package, so `node_modules/rush-order-pwa` doesn't exist by default — but the converter's `PKG_DIR` resolution (both the top-level `exportedNames` sanity call and `resolvePackage`'s `srcRoot` discovery via `cfg.srcDir`) needs it to exist as a real, fully-populated view of the package root, or the build crashes (`ENOENT ... node_modules/rush-order-pwa/package.json`) or silently degrades to zero components. `--entry` is NOT a substitute here — passing it makes `resolveDistEntry` treat that single file AS the dist entry, which skips the synth-from-src fallback entirely and produces a 0-component "tokens-only" bundle. Fix: a Windows **directory junction** (not a symlink — `ln -s` without elevated privileges silently produces a broken partial copy instead of erroring cleanly, wasting a lot of time chasing it):
  ```powershell
  cmd /c "mklink /J `"node_modules\rush-order-pwa`" `".`""   # run with cwd = pwa/
  ```
  Recreate this after any fresh clone or `node_modules` wipe/reinstall (gitignored, doesn't survive `npm ci`).
- **Single-mode overlay previews (`fixed inset-0`) need a normal-flow height spacer.** The `cardMode: 'single'` wrapper (`.ds-single`) has `transform:translateZ(0)`, making it the CSS containing block for `position:fixed` descendants — but if the preview's entire returned tree is itself `position:fixed` (Modal's outer div), the wrapper has no in-flow content to size its own height against, collapses toward 0, and the fixed child's flex-centering then centers around that near-zero point — pushing roughly the top half of the dialog above the visible capture area. Fix used in `Modal.tsx`: render an explicit `<div style={{height: N}} aria-hidden />` spacer as a sibling before the real component, standing in for the ambient page height the real app always provides underneath a modal. `PwaInstallBanner`/`ToastContainer` didn't need this because their own preview wrapper divs (`position:'relative', height:N`) already provide that in-flow height.
- **i18n-dependent components (`SkipLink`, `PwaInstallBanner`) need `cfg.extraEntries`, not a per-preview import.** Each `.design-sync/previews/<Name>.tsx` compiles into its own SEPARATE esbuild bundle (`_preview/<Name>.js`), independent from the main `_ds_bundle.js` that the actual exported components ship in — so `import '../../src/app/i18n'` inside a preview file initializes a *different* bundled copy of the `i18next` singleton than the one `useTranslation()` reads from inside the real component, and text still shows raw keys (`pwa.installTitle`). Fix: `cfg.extraEntries: ["./src/app/i18n.ts"]` merges the i18n init module into the SAME esbuild pass as the main entry (`.bundle-entry.mjs` does `export * from <extraEntry>; export * from <mainEntry>`), so it shares one `i18next` instance with the real components. Confirmed real Spanish copy renders after this change.

## Known render warns (triaged, expected on every re-sync)

- `[RENDER_THIN] Spinner.html: mounts have no text and paint nothing` — false positive. `Spinner` is an icon-only SVG with no text by design; the screenshot (`_screenshots/general__Spinner.png`) shows three correctly-styled red spinner icons at sm/md/lg. Confirmed visually — not a real rendering problem.

## Re-sync risks

- The `tailwind-build.css` copy is the single biggest thing that can silently go stale — if a re-sync skips the `npx vite build` step, the bundle will still reference real class names, but the shipped CSS won't have rules for anything added/changed in Tailwind config or component markup since the last build.
- These 7 components are internal app UI primitives, not a deliberately designed public component library — expect the API surface (props) to be narrower/less polished than a real design system's, and expect this list to grow as `shared/components/` grows. Re-check `src/shared/components/*.tsx` on every re-sync for new files.
- `Modal.tsx` and `PwaInstallBanner.tsx` depend on app-level hooks (`useFocusTrap`, `usePwaInstall`, `useAnalytics`) via `@shared/hooks/*` — these get bundled in (not mocked), so their preview behavior depends on those hooks tolerating a non-router, non-provider-wrapped render context. Watch for `[RENDER]`/provider errors here first if either preview fails.
